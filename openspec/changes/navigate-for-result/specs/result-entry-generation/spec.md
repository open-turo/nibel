# Spec Delta

## Purpose

Lets screens declare the type of result they return, so the compiler generates typed entries for them and rejects callers, destinations and declarations whose result types don't match.

## ADDED Requirements

### Requirement: Entry annotations declare a result type

`@UiEntry`, `@UiExternalEntry`, `@LegacyEntry` and `@LegacyExternalEntry` SHALL accept an optional result type. Omitting it SHALL mean the screen returns no result.

#### Scenario: Screen declares a result

- **WHEN** a composable is annotated with `@UiEntry` and a result type `R`
- **THEN** the build succeeds and the screen is treated as returning `R`

#### Scenario: Legacy fragment declares a result

- **WHEN** a fragment is annotated with `@LegacyEntry` or `@LegacyExternalEntry` and a result type `R`
- **THEN** the build succeeds and the fragment is treated as returning `R`

#### Scenario: No result declared

- **WHEN** a screen is annotated without a result type
- **THEN** the generated code is identical to the code generated by the previous version

### Requirement: Result types are valid parcelables

A declared result type SHALL be a `Parcelable` data class or object without type parameters. Any other declaration SHALL fail the build with an error pointing at the annotated screen.

#### Scenario: Generic result type

- **WHEN** a screen declares a result type with type parameters
- **THEN** the build fails with an error saying result types can't be generic

#### Scenario: Result type is a regular class

- **WHEN** a screen declares a result type that is neither a data class nor an object
- **THEN** the build fails with an error saying result types must be a data class or an object

### Requirement: Typed entries for screens with a result

For each screen that declares a result type `R`, the generated entry SHALL provide a factory that returns an entry typed with `R`, taking the same args as the regular factory. The regular factory SHALL stay available and unchanged.

#### Scenario: Typed factory

- **WHEN** a screen declares result type `R` and args type `A`
- **THEN** its generated entry offers a factory that takes `A` and returns an entry typed with `R`

#### Scenario: Regular factory still available

- **WHEN** a screen declares a result type
- **THEN** its generated entry still offers the regular factory, usable with regular navigation

### Requirement: Caller and screen result types must match

Navigating for a result with a typed entry or a destination with a result SHALL compile only when the launcher's result type equals the screen's result type.

#### Scenario: Matching types

- **WHEN** a caller navigates for a result to an entry typed with `R` using a launcher for `R`
- **THEN** the code compiles

#### Scenario: Mismatched types

- **WHEN** a caller navigates for a result to an entry typed with `R` using a launcher for a different type `S`
- **THEN** the code doesn't compile

#### Scenario: Entry without a result

- **WHEN** a caller navigates for a result to an entry whose screen declares no result
- **THEN** the code doesn't compile

### Requirement: Destinations declare their result type

An external destination SHALL be able to declare the result type of its screen, in addition to declaring args or no args. Navigating for a result to an external destination SHALL require the destination to declare a result type.

#### Scenario: Destination with args and a result

- **WHEN** a destination declares args type `A` and result type `R`
- **THEN** a caller can navigate for a result to it with a launcher for `R`

#### Scenario: Destination without a result

- **WHEN** a caller navigates for a result to a destination that declares no result type
- **THEN** the code doesn't compile

### Requirement: Destination and screen result types must agree

For an external entry, the compiler SHALL fail the build when the destination's result type and the annotation's result type differ, or when only one of them declares a result.

#### Scenario: Types differ

- **WHEN** a screen annotated with result type `R` is associated with a destination that declares result type `S`
- **THEN** the build fails with an error naming both types

#### Scenario: Only the destination declares a result

- **WHEN** a destination declares result type `R` and its associated screen's annotation declares no result
- **THEN** the build fails with an error asking to declare `R` on the annotation

#### Scenario: Only the annotation declares a result

- **WHEN** a screen's annotation declares result type `R` and its destination declares no result
- **THEN** the build fails with an error asking the destination to declare `R`

### Requirement: Plain fragments opened for a result

A caller SHALL be able to open a plain fragment for a result by stating its result type explicitly.

#### Scenario: Plain fragment with an explicit result type

- **WHEN** a caller wraps a plain fragment as an entry typed with `R` and navigates for a result with a launcher for `R`
- **THEN** the code compiles and the fragment's result is delivered to the launcher
